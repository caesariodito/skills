# Rationale prompts

Use only relevant rows; accepted decisions belong in lifecycle spec, not separate authority.

| Topic | Evidence to capture |
|---|---|
| Problem | User outcome, current limitation and non-goals |
| Usage | Realistic call/site or user journey before internal types |
| Shape | Data/ownership, boundaries, invariants, transformations and recovery |
| Alternatives | Materially different options; why chosen shape wins on actual criteria |
| Trade-offs | What we accept, missing capabilities, operational/migration cost |
| Future | Documented expected use, deliberate ceiling and concrete revisit trigger |
| Uncertainty | Assumption, cheapest experiment and decision needing human |
| Next step | Smallest verifiable implementation slice after approval |
